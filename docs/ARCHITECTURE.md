# مستند جامع معماری سیستم (System Architecture)

پروژه **Bale Telegram Viewer** یک سامانه سبک، سرورلس (Serverless) و ۱۰۰٪ رایگان جهت مطالعه پست‌های کانال‌های عمومی برگزیده تلگرام از داخل پیام‌رسان «بله» بدون نیاز به VPN در ایران است.

---

## ۱. اهداف و محدودیت‌های کلیدی

### اهداف:
1. دسترسی مستقیم و بدون فیلتر به محتوای کانال‌های عمومی تلگرام داخل کشور.
2. رابط کاربری بسیار روان و شبیه‌سازی‌شده دقیق تلگرام به صورت راست‌چین (RTL) و فارسی.
3. سازگاری خودکار با تم روشن و تاریک بله از طریق `themeParams`.
4. هزینه عملیاتی دقیقاً صفر تومان (بدون سرور اختصاصی، بدون VPS و بدون Cloudflare).

### محدودیت‌های قطعی:
* بدون نیاز به ورود به اکانت تلگرام یا داشتن Session/API Key تلگرام (فقط اسکرپ صفحات وب عمومی `t.me/s/<channel>`).
* بدون پایگاه‌داده متمرکز و سرور بک‌اند؛ میزبانی کامل داده‌ها بر روی GitHub Pages.
* بدون ارسال پیام یا پاسخ؛ حالت سامانه کاملاً **فقط-خواندنی (Read-Only)** است.

---

## ۲. طراحی زیرساخت و جریان داده (Zero-Server Architecture)

```
[ GitHub Actions (Cron) ] 
       │
       ▼
[ Collector Script (Python) ] ──(Scrapes)──> [ https://t.me/s/<channel> ]
       │
       ├─ استخراج متن، تاریخ، آمار، واکنش‌ها
       ├─ دانلود و تبدیل تصاویر به WebP (حداکثر عرض 1080px، کیفیت 75%)
       ├─ پاکسازی پست‌ها و فایل‌های قدیمی‌تر از 7 روز (Sliding Window)
       │
       ▼
[ Git Push to gh-pages Branch ] (تک کامیت بدون ذخیره تاریخچه - ضد بادکردن مخزن)
       │
       ▼
[ GitHub Pages CDN ] ──(اینترنت آزاد در ایران)──> [ مینی‌اپ در پیام‌رسان بله ]
```

### استراتژی مقابله با بادکردن مخزن (Anti-Bloat Strategy):
یکی از گلوگاه‌های اصلی در پروژه‌های اتوماسیون گیت‌هاب، ذخیره مکرر فایل‌های تصویری در تاریخچه گیت است. اگر هر ۵ یا ۱۰ دقیقه عکسی تغییر کند و کامیت معمولی زده شود، پوشه `.git` ظرف چند هفته چند گیگابایت حجم پیدا می‌کند و گیت‌هاب اکانت را اخطار می‌دهد.
* **راهکار معماری:** تمام خروجی‌های داده و تصاویر تولیدشده به صورت یک شاخه یتیم (`orphan branch`) به نام `gh-pages` مستقر می‌شوند. با استفاده از روش `--force push` تک‌کامیت، فقط آخرین عکس‌ها و فایل‌های JSON در شاخه قرار می‌گیرند و تاریخچه نسخه‌های حذف‌شده ذخیره نمی‌شود.
* مخزن کدهای اصلی در شاخه `main` دست‌نخورده باقی می‌ماند و حجم کل پروژه برای همیشه زیر **۳۰ مگابایت** باقی خواهد ماند.

---

## ۳. پایپ‌لاین جمع‌آوری داده (Collector Pipeline)

1. **خواندن پیکربندی:** خواندن تنظیمات از `config/channels.json`.
2. **دریافت صفحه وب:** ارسال درخواست به `https://t.me/s/<channel_id>` با هدرهای مرورگر واقعی دسکتاپ و تاخیر تصادفی ۲ الی ۴ ثانیه‌ای بین کانال‌ها برای محافظت از مسدودسازی توسط ریت‌لیمیت تلگرام.
3. **پارس ساختار HTML تلگرام:**
   * بخش متن: استخراج متن تگ `.tgme_widget_message_text` و حفظ تگ‌های بی‌خطر قالب‌بندی (`b`, `i`, `u`, `s`, `code`, `pre`, `a`).
   * عکس‌ها: استخراج آدرس تصویر پس‌زمینه از `.tgme_widget_message_photo_wrap`، دانلود و ذخیره محلی با فشرده‌سازی WebP.
   * ویدیوها: عدم دانلود ویدیوی سنگین؛ استخراج تصویر کاور (Thumbnail) و ثبت کارت پیوند برای باز شدن در اپ تلگرام.
   * نقل‌قول و فوروارد: شناسایی ریپلای به پیام دیگر یا فوروارد از سایر کانال‌ها.
4. **تولید خروجی:** ساخت `data/<channel_id>.json` و بروزرسانی `data/index.json`.

---

## ۴. رابط کاربری مینی‌اپ (Telegram-like SPA)

1. **فناوری:** Vanilla JavaScript (بدون وابستگی سنگین یا زمان بیلد پیچیده).
2. **پشتیبانی تم بله:**
   * اتصال به شیء `window.Bale.WebApp.themeParams`.
   * همگام‌سازی متغیرهای CSS روت (`--bg-color`, `--text-color`, `--bubble-in`, `--bubble-out`).
3. **مدیریت وضعیت (State Management):**
   * آخرین پست خوانده‌شده در هر کانال داخل `localStorage` ذخیره می‌شود.
   * در صورت انتشار پست جدیدتر در فایل ایندکس، نشانگر اعلان قرمز (Badge) روی آیکون کانال مربوطه نمایش داده می‌شود.
4. **سازگاری با وب‌کلاینت و موبایل بله:**
   * متدهای `Bale.WebApp.ready()` و `Bale.WebApp.expand()` در ابتدای لود صدا زده می‌شوند.
   * از فراخوانی متدهای مسدودشده در iframe خودداری می‌شود.
